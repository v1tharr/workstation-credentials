# Разработка

Карта проекта для тех, кто будет вносить изменения (в том числе вместе с ИИ-помощником).

## Запуск и тесты

```bash
pip install -r requirements-dev.txt
pytest

export $(python manage.py gen-keys | xargs) DB_PATH=/tmp/demo/creds.db
python manage.py demo
gunicorn --bind 127.0.0.1:8765 'app:create_app()'
```

Тесты (`tests/`) поднимают приложение с временной базой и проходят по основным сценариям: вход, выдача кода,
активация, шифрование, импорт и экспорт, редактор мероприятия. Перед изменением логики запустите `pytest`,
после изменения запустите снова. GitHub Actions делает то же самое на каждый пуш и pull request.

Участник и админ должны быть в разных браузерах или в обычном окне и инкогнито: иначе у них общая сессия.

## Устройство

Flask-приложение, фабрика `create_app()` в `app/__init__.py`. Данные в SQLite, пароли рабочих мест шифруются.

| Файл | За что отвечает |
|---|---|
| `app/__init__.py` | сборка приложения, заголовки безопасности, CSRF, обработчики ошибок |
| `app/config.py` | настройки из переменных окружения (в том числе `*_FILE` для Docker secrets) |
| `app/db.py` | схема SQLite и подключение |
| `app/crypto.py` | шифрование данных рабочих мест, проверка ключа при старте |
| `app/auth.py` | администраторы: вход, пароли, роли, блокировка |
| `app/student.py` | страница участника: код, ожидание, показ карточек |
| `app/admin.py` | админка: коды, мероприятия, места, админы, журнал |
| `app/util.py` | разбор полей и карточек, импорт/экспорт, подстановка данных в карточки |
| `app/presets/` | готовые шаблоны мероприятий (JSON) |
| `manage.py` | команды: `gen-keys`, `create-admin`, `import-json`, `demo` |

Модель данных: мероприятие (`exams`) описывает колонки данных и карточки страницы участника (JSON).
У него есть рабочие места (`slots`), данные каждого зашифрованы. Участник получает код (`sessions`),
организатор привязывает код к месту. На одно место может быть не больше одного активного участника
(это гарантирует уникальный индекс в базе).

## Интерфейс

- Шаблоны: `app/templates/` (страница участника в корне, админка в `admin/`).
- Стили: `app/static/app.css` общие и для участника, `app/static/admin.css` только для админки.
  Тема админки переключается атрибутом `data-theme` на `<html>`, цвета заданы переменными в начале `admin.css`.
- Скрипты: `app.js` (копирование, подтверждения, поиск в таблицах, ожидание), `combo.js` (выпадающие списки),
  `editor.js` (редактор полей и карточек с превью), `admin-theme.js` (тема).

Важное ограничение: политика безопасности (`Content-Security-Policy`) запрещает встроенные скрипты и стили,
поэтому JS и CSS лежат в отдельных файлах, а данные в разметку передаются через `data-` атрибуты.

## Правила, которые легко нарушить

- Любой POST-запрос должен нести CSRF-токен (`csrf_token` в форме).
- Пароли рабочих мест нигде не пишутся открытым текстом: ни в базу, ни в журнал, ни в логи.
- Лимит запросов по IP: с ним осторожнее. В Docker Desktop (WSL) и при обращении через localhost приложение
  видит один адрес шлюза для всех клиентов, а при общем NAT или неверной настройке прокси адреса тоже
  оказываются недостоверными. Раньше из-за этого посетителей блокировало ошибкой 429. Сейчас защита от
  переполнения не зависит от IP: потолок ожидающих кодов (`MAX_PENDING`), старые вытесняются.
- Структура базы сейчас создаётся только командами `CREATE TABLE IF NOT EXISTS`. Автоматических миграций нет:
  если меняете схему, продумайте, как существующая база получит изменения.

Шрифты Inter и JetBrains Mono лежат в `app/static/fonts` (лицензия OFL, тексты лицензий рядом).
