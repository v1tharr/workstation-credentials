# Развёртывание на сервере

Рассчитано на такую схему: сервис живёт на сервере учебного заведения, к нему ходят по доменному имени
из внутренней сети, а перед ним стоит reverse-proxy с HTTPS. Нужны Docker с плагином Compose и `python3` на хосте
(для генерации ключей в `setup.sh`).

**1. Код и ключи**

```bash
git clone https://github.com/v1tharr/workstation-credentials.git
cd workstation-credentials
./setup.sh                    # создаёт .env с ключами; если .env уже есть, не трогает его
```

Сразу сохраните копию `ENCRYPTION_KEY` из `.env` отдельно от сервера (менеджер паролей, сейф).
Без неё не восстановить данные после потери сервера.

**2. Настройки под прокси.** Добавьте в `.env`:

```
LISTEN_ADDR=127.0.0.1         # порт сервиса доступен только самому серверу, наружу идёт прокси
TRUST_PROXY=1
COOKIE_SECURE=1
```

`TRUST_PROXY=1` нужен, чтобы в админке были видны адреса участников, а не адрес прокси.
`COOKIE_SECURE=1` отправляет cookie только по HTTPS. Не включайте его, пока HTTPS не настроен: вход в админку
перестанет работать.

**3. Запуск и первый владелец**

```bash
docker compose up -d --build
docker compose exec web python manage.py create-admin
```

Проверьте, что сервис отвечает на самом сервере: `curl -I http://127.0.0.1:8765/admin/login`.

**4. Reverse-proxy.** Любой на ваш выбор. Он должен проксировать на `127.0.0.1:8765` и передавать заголовки
`X-Forwarded-For` и `X-Forwarded-Proto`. Примеры (для вашей установки подставьте свой домен):

Caddy (сам получает сертификат для публичного домена; нужные заголовки ставит по умолчанию):

```
creds.example.edu {
    reverse_proxy 127.0.0.1:8765
}
```

nginx (сертификат подключите своим способом):

```
server {
    listen 443 ssl;
    server_name creds.example.edu;
    # ssl_certificate и ssl_certificate_key

    location / {
        proxy_pass http://127.0.0.1:8765;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Nginx Proxy Manager:

1. Proxy Host: доменное имя сервиса, схема `http`, порт `5000`.
2. Вкладка SSL: выберите сертификат (Let's Encrypt или загруженный свой) и включите «Force SSL».
3. Адрес для пересылки зависит от того, где запущен NPM.
   - NPM в Docker на том же сервере: подключите его к сети сервиса и укажите имя контейнера.
     Имя сети смотрите в `docker network ls`, обычно это `<имя папки>_default`:

     ```bash
     docker network connect workstation-credentials_default <имя контейнера NPM>
     ```

     В NPM: Forward Hostname `exam_credentials` (имя контейнера из `docker-compose.yml`), порт `5000`.
   - NPM на другой машине: уберите `LISTEN_ADDR=127.0.0.1`, укажите в NPM адрес сервера и порт `8765`,
     а в файрволе сервера разрешите этот порт только адресу NPM.

В nginx для загрузки CSV и JSON добавьте `client_max_body_size 2m;` (по умолчанию nginx принимает только 1 МБ,
а приложение допускает до 2 МБ).

**Сертификат**

- **Let's Encrypt.** Нужен публичный домен. Обычная проверка (HTTP-01) требует, чтобы сервер был доступен из
  интернета по порту 80. Если сервис только во внутренней сети, а домен публичный и указывает на внутренний адрес,
  сертификат можно получить через проверку по DNS (DNS-01): её поддерживают certbot и NPM для ряда DNS-провайдеров.
  Для внутренних имён вроде `.local` Let's Encrypt сертификат не выдаёт.
- **Самоподписанный или от своего центра сертификации.** Подходит для закрытой сети. Чтобы браузеры не предупреждали,
  добавьте сертификат (или корневой сертификат вашего центра) в доверенные на рабочих местах. Иначе участники
  будут видеть предупреждение при каждом заходе.

После настройки проверьте: сайт открывается по `https://домен/` без предупреждений, вход в админку работает,
а в списке кодов у участников виден их адрес, а не адрес прокси.

Админка находится по адресу `/admin/`. Если доступ к ней нужно ограничить подсетью организаторов,
это делается на прокси (например, `allow`/`deny` в nginx для `location /admin/`). Сам сервис такого ограничения не делает.

**5. Файрвол.** Откройте наружу только 443 (и 80, если прокси перенаправляет на HTTPS). Порт 8765 при
`LISTEN_ADDR=127.0.0.1` снаружи недоступен.

**Попробовать без настройки:** `docker compose exec web python manage.py demo` создаёт владельца `owner`
с паролем `demo-owner-pass` и два мероприятия с выдуманными данными. Только для тестовой установки.
