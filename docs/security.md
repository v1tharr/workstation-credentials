# Безопасность и ограничения

Что сделано:

- Пароли рабочих мест в базе шифруются (Fernet) ключом `ENCRYPTION_KEY`. Пароли администраторов хранятся хэшем (scrypt).
- Приложение не запускается без ключей. Паролей по умолчанию нет.
- Вход администратора с блокировкой после пяти неверных попыток, журнал действий.
- CSRF-токены на всех POST-запросах, заголовки `Content-Security-Policy` и `X-Frame-Options`,
  `Cache-Control: no-store` для страниц с паролями.
- Страницы участника и админки не используют внешние ресурсы: шрифты лежат в проекте.

Что нужно знать:

- Пароли рабочих мест хранятся обратимо. Это намеренно: участнику нужно их показать. Защита в том, что
  без ключа база и её бэкапы нечитаемы.
- Сервис сам по себе отдаёт HTTP. Если он доступен не только в изолированной сети мероприятия,
  поставьте перед ним reverse-proxy с HTTPS.
- Код, который видит участник, ничем не защищён, кроме подтверждения организатором: любой, кто открыл сайт, получает код.
  Доступ к данным даёт только активация организатором.
- Независимого аудита безопасности не проводилось.
- База SQLite. В локальных нагрузочных тестах (gunicorn, 200 одновременных клиентов) это не было узким местом.
  Для одной установки на одно учебное заведение этого достаточно.
