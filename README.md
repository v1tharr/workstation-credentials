# exam-credentials

Сервис выдачи учётных данных рабочих мест на экзаменах. Участник открывает сайт и получает
6-значный код, технический эксперт в панели привязывает код к рабочему месту конкретного экзамена,
и страница участника сама показывает его логины и пароли.

Одним инстансом можно вести несколько экзаменов одновременно (программирование, ИБ, …):
у каждого свои поля, свои карточки и свои рабочие места.

## Где что хранится

| Что | Где |
|---|---|
| `SECRET_KEY`, `ENCRYPTION_KEY` | `.env` (или Docker secret через `*_FILE`), в git не попадает |
| Пароли рабочих мест | в SQLite, **зашифрованы** (Fernet) ключом `ENCRYPTION_KEY` |
| Пароли администраторов | в SQLite, хэш (scrypt) |
| Экзамены, колонки, карточки, места | SQLite, редактируются в админке |

Приложение не стартует без `SECRET_KEY` и `ENCRYPTION_KEY`; дефолтных паролей нет.
Пароли станций остаются обратимыми намеренно: участнику их надо показать.
Защита в том, что в БД и бэкапах их не прочитать без ключа, а ключ лежит отдельно.

## Запуск

```bash
./setup.sh                           # создаёт .env с ключами; если .env уже есть — не трогает
docker compose up -d --build
docker compose exec web python manage.py create-admin     # первый владелец, пароль спросит интерактивно
```

Участники: `http://<IP>:8765/`  Админка: `http://<IP>:8765/admin/`

Дальше всё делается в админке:

1. **Админы** — владелец заводит остальных админов (роль `admin` или `owner`).
2. **Экзамены → Новый экзамен** (можно «по образцу» другого экзамена).
3. В экзамене на вкладке **«Данные и страница участника»**: сначала список полей, которые вводятся для каждого места
   (например «Логин», «Пароль»), затем карточки, которые увидит участник. Для каждого поля карточки выбирается источник:
   *данные рабочего места* (у каждого места своё) или *свой текст* (одинаково у всех). Справа живое превью страницы участника.
   Вкладка **«JSON»** — то же самое текстом, для тех, кому так удобнее.
   Быстрый старт: при создании экзамена выбрать **готовый шаблон** (программирование, ИБ) или **«по образцу»** другого экзамена.
4. На вкладке **«Рабочие места»** загрузить места из CSV (заготовку с заголовком можно скачать) или добавить руками.
   Первое поле данных служит названием места в списках.
5. В день экзамена: участник открывает сайт, называет код, вы на вкладке «Коды» выбираете место и жмёте
   «Активировать». Параллельные экзамены — просто места из разных экзаменов в одном выпадающем списке.
6. После экзамена: **«Закрыть экзамен»** отключает всех участников; **«Удалить»** стирает учётные данные.

Перенос между инсталляциями: у экзамена есть **«Скачать шаблон»** (колонки и карточки, без паролей), а на странице
«Экзамены» — **«Создать из JSON»**. Туда же можно загрузить старый `config.json` (список записей) или шаблон с полем
`slots`, тогда места создадутся сразу.

Миграция со старого `config.json` из командной строки:

```bash
docker compose cp config.json web:/tmp/config.json
docker compose exec web python manage.py import-json /tmp/config.json --exam "Название" \
        --cards examples/cards.example.json
docker compose exec web rm /tmp/config.json   # и удалить исходный файл у себя
```

## Проверка дома

```bash
pip install -r requirements-dev.txt
pytest                                    # автотесты, 46 шт.

export $(python manage.py gen-keys | xargs) DB_PATH=/tmp/demo/creds.db
python manage.py demo                     # админ owner / demo-owner-pass, два экзамена с фейковыми данными
gunicorn --bind 127.0.0.1:8765 'app:create_app()'
```

Участник и админ — два разных браузера (или обычное окно и инкогнито), cookie у них отдельные.

## Что изменилось по сравнению с первой версией

- Секреты и учётки больше не лежат в JSON/compose: ключи в `.env`, пароли станций шифруются.
- Админ-вход по логину и паролю из БД (несколько админов, роли, блокировка после 5 неверных попыток, журнал действий).
- Много экзаменов, поля и карточки настраиваются в админке, а не в коде.
- Неактивированные коды протухают через 30 минут, плюс общий потолок (`MAX_PENDING`, старые вытесняются).
  Раньше таблица выросла до ~195 тысяч «pending»-строк: healthcheck заходил на `/` без cookie и каждый раз создавал код.
- CSRF-токены, POST для выхода, CSP, `Cache-Control: no-store` для страниц с паролями.
- Шрифты Inter и JetBrains Mono лежат в проекте (`app/static/fonts`, лицензия OFL): интернет не нужен, вид не зависит от клиента.
- БД лежит в Docker volume, ручной `chown 1001` больше не нужен.

## Эксплуатация

- **Бэкап:** `docker compose exec web python -c "import sqlite3;s=sqlite3.connect('/app/data/creds.db');s.backup(sqlite3.connect('/app/data/backup.db'))"`,
  затем забрать `backup.db`. Ключ `ENCRYPTION_KEY` хранить отдельно: без него бэкап нечитаем.
- **HTTPS:** за reverse-proxy поставить `TRUST_PROXY=1` и `COOKIE_SECURE=1`, иначе в админке будет виден IP прокси.
- **Забыли пароль владельца:** `docker compose exec web python manage.py create-admin` создаст нового владельца.
